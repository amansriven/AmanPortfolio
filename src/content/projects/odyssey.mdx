## What it is

When a health claim is denied, the member usually finds out through silence — and then
spends a phone call learning what happened. Odyssey moves that explanation earlier. It
reads a claim, works out what went wrong, decides whether it is fixable, and produces a
plain-language account of what happened, who needs to act, and what the next step is.

When something genuinely needs a person, it hands the representative a case summary that
was already assembled, so the call starts at the answer rather than at the beginning.

It was built for a Humana hackathon on a fully synthetic dataset — no real member data
was involved — and it won first place.

## The decision I would defend hardest

<Callout label="Decision" title="The solvability router was an LLM call. I demoted it to code.">
  Deciding whether a denied claim is fixable is a factual determination. It changes what a
  member is told to do next, and being wrong about it wastes their time in a system that
  already wastes a lot of it.

The original design had an agent make that call. It worked most of the time, which is the
dangerous kind of working. By the time the Mediator has finished reconciling the
researchers, the answer already exists as a boolean in state — so the router became a
`BaseAgent` subclass that reads it. Deterministic, unit-testable against ground truth in
the dataset, and still visible in the execution trace.

The rule that fell out of it and then governed the whole system: **agents explain
findings, they do not decide facts.**

</Callout>

## Concurrency, and paying for reliability with latency

Two parallel researcher agents issuing three tool calls each produced six concurrent
calls against Vertex AI. That is a perfectly reasonable thing to want and a reliable way
to hit a rate limit mid-run — which, in a demo, means the pipeline dies in front of an
audience.

I serialized those six calls. It cost about five seconds of end-to-end latency and it
made the failure mode go away. For a system whose output a representative reads before
picking up a phone, five seconds is not a currency anyone is counting; a run that dies
halfway through is.

<Callout label="Tradeoff" title="Bounded loops over clever recovery">
  The Mediator can reject its researchers and try again, which is exactly the shape that turns into
  two agents arguing forever. It is capped at two iterations with a deterministic exhaustion path
  into escalation. The exhaustion path is a feature, not a fallback — when the agents cannot reach
  confident consensus, the system does not fabricate an answer, it hands a human everything it
  found.
</Callout>

## What it is worth

The headline is that it uses nine agents. That is the least interesting thing about it.
The part I would actually put in front of an engineer is the subtraction: an agent that
was removed because a boolean already existed, a loop that was capped because it could
otherwise run forever, and five seconds of latency traded away to stop a rate limiter
from ending the run.
